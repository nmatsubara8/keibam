## 0. 確定済みの事実

### 0.1 左辺キー = 既存 race_key + umaban（✅ `src/jrdb/_keys.py` で照合済）

外厩コメントの左辺 10 桁キー（例 `0126120103`）は **新しい変換規則を要さない**。

```
0126120103 = race_key(8) + umaban(2)
  01  26  1   2      01   03
  場  年  回  日(hex) R    馬番     → 札幌 2026 1回2日目 1R 3番
```

```python
from src.jrdb._keys import race_key_to_race_id
race_id = race_key_to_race_id(key[:8])   # 日は16進1桁・世紀補完(pivot=86)込み
umaban  = int(key[8:10])
# (race_id, umaban) で featured / KYI / SED と結合 ← 既存 JRDB join と同一キー
```

- **日は 16 進 1 桁**（10〜15 日目 = a〜f）。左辺を 10 進で桁分割しないこと。
- ファイル名 `YC012612.DAT` = `YC` + 開催キー6桁（`01`場 `26`年 `1`回 `2`日）。**1 ファイル = 1 開催**。

## 3. 外厩コメントの構造（✅ 日次 `gaikyucomment_20260726.zip` を現物解析＝確定）

- **自由記述テキストではなく定型構造化文字列**を確定 → NLP 不要・辞書/embedding 不要。
- 配布/ファイル形式（現物確認済）:
  - 日次 ZIP 名 = `gaikyucomment_<YYYYMMDD>.zip`。
  - ZIP 内 = 開催ごとに `YC<開催6桁>.DAT`（例 `YC012612.DAT` = 場01年26回1日2）。1 開催 = 1 ファイル。
  - **CP932 / CRLF / ヘッダなし CSV / 1 行 1 頭 / カンマ 1 個**。
  - 左辺 = 10 桁キー、右辺 = `外厩名　MM/DD　中N週`（区切りは全角スペース `　`）。
- 抽出列: `target_key` / `raw_comment`（無加工保持）/ `gaikyu_name` / `gaikyu_date_raw`(MM/DD) / `interval_weeks`。
- 派生: `has_gaikyu`（この左結合に**存在するか**＝外厩利用の有無。ファイルは外厩利用馬のみ収録）/
  `days_since_return`（帰厩日→出走日。ただし出走日は race_id から別途取得）。

### 3.1 確定パーサ正規表現（日次サンプルで 284/284 = 100%）

週数を**任意**にするのが唯一の修正点（`中週`＝週数空欄が 30/284 存在）:

```python
COMMENT_RE = re.compile(
    r"^(?P<gaikyu_name>.+?)　(?P<month>\d{2})/(?P<day>\d{2})　中(?P<weeks>\d*)週$"
)
# weeks == "" → interval_weeks = None
```

- 全角数字・`連闘`・`初戦`・`放牧` は日次サンプルに **0 件**（＝この開催では発生せず。全年度で要再確認）。

### 3.2 `中N週` の意味 = 前走からの競走間隔（✅ 実証・滞在週数ではない）

帰厩日と桁が桁違いに乖離する実例で確定:

```
ダーレー・ジャパン  帰厩07/10(出走2026-07-26の16日前)  だが 中44週(=308日)
ビッグレッドＦ鉾田  帰厩06/19(出走の37日前)          だが 中55週(=385日)
```

- **MM/DD = 外厩から厩舎へ戻った帰厩日**（直近 16〜45 日）、**中N週 = 前走からの競走間隔**（最大 55 週）。両者は別概念。
- `中N週` を「外厩滞在週数」とみなしてはならない（特徴設計の禁止事項 §6.1 に反映済）。
- 週数空欄（`中週`）30 件は前走なし（初出走等）の可能性 → `interval_weeks = None`。SED 前走日との突き合わせで最終確認する。

### 3.3 残る未確定（要追加サンプル）

- **年次ファイル**が日次と同一形式か（`gaikyucomment_<YYYY>.zip`?・キー長・`中N週`表記・例外語）。
- 全年度での例外語（`連闘`/`初戦`/地方・海外馬/年越し日付）の実発生と網羅。
- `中N週` = SED 前走間隔と厳密一致するかの数値照合（このコンテナに SED 実データが無いため保留）。

## 6. A: 外厩運用情報の純増分検証（B/C 確定後に着手）

研究テーマは「外厩コメントのテキスト分析」ではなく **「外厩運用情報の構造化特徴量としての純増分検証」**。

### 6.1 特徴量（すべて過去走のみ・fold 以前）

- 低コスト: `has_gaikyu` / `gaikyu_name` / `days_since_return` / `interval_weeks` /
  `gaikyu_name × interval_weeks` / `gaikyu_name × trainer`
- 履歴集約: 外厩別複勝率 / 外厩別 market-residual / 外厩×厩舎別成績 / 休み明け成績 /
  同一外厩継続利用時の成績 / 外厩変更時の成績
- **避ける**: 全期間 target encoding / 評価期間を含む集約 / 出走後更新ファイルの利用 /
  稀少外厩の高次元 one-hot / `中N週` を外厩滞在週数とみなすこと

### 6.2 段階ゲート（MySpeed 流・過去走のみ厳守）

1. **Phase 0 情報独立性**: 新feature vs 市場(IDM/基準オッズ/人気/確定オッズ)の相関・偏相関。冗長なら即棄却。
2. **Phase 1 較正ゲート**: OOS で ΔNLL/ECE を `_model_compare`、placebo 2軸(残差/オッズ)対照。
3. **Phase 2 ROIゲート（唯一の合否）**: `multibet_roi_test` のレース単位ブロック bootstrap **95%CI下限>1.0**。
   帯・サブセット選択は train のみ、多重比較は placebo で検定。
4. **Phase 3 運用配線**: 通れば EV較正＋損失最小化へ。通らなければ「効率市場の再確認」として記録。
