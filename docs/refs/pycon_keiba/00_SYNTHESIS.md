## 批判的評価 — 「回収123%」は保留

keibam の結論（JRA単勝は効率的・エッジ無し: ΔR²<0, echo 0.939）と正面から矛盾する。疑う理由:

1. **Target Encoding は静かなリーク源**。集計特徴を時間前方（過去レースのみ / out-of-fold）で作らないと目的変数が染み出す（`rank_win` の巧妙版）。トークは race-wise CV でレース内リークは防ぐが、**集計特徴の時間リーク**には触れていない → 123% の最有力容疑。
2. **回収率は分散が巨大**（トーク自身が std を指標に挙げる）。限られた標本の123%は100%と統計的に区別できない可能性。
3. **選抜バイアス**（高EVのみ買う等で n が小さいと123%は容易に出る）。
4. 2018年・データ源の違い（市場効率は年で変動）。

→ ランキング品質の実改善は本物の可能性が高いが、**>100%回収への飛躍だけは keibam 自身の OOS＋リーク検査を通すまで採用しない**。

## 最重要の含意 — 「結論は暫定」を裏付ける

トークは **「出走履歴の集計特徴が最も効くデータ源」** と明言。keibam はその form 特徴を **93–96% 欠損**し、現在 backfill 中。
**＝ keibam が「エッジ無し」と結論した時、本トックが"最強"と呼ぶ特徴量がほぼ丸ごと欠けていた。**
本トークは「form データを揃えるまで市場効率の結論は暫定」という判断の外部裏付けであり、backfill 完遂が最高価値の一手であることを再確認させる。

## keibam への実装レシピ（backfill 完了後）

1. **entity×context×集計特徴**を、**必ず時間前方（過去レースのみ）で生成** → 追加ごとに `debug_leak.py`（単一特徴 AUC>0.9）で漏れ確認。
2. **スムージング**（少数カテゴリ→全体平均、α=相互情報量）を集計特徴へ付与（欠損の多い現データに特に有効）。
3. 評価に **NDCG（着順/賞金/単勝支持率）** を追加。特に **「着順NDCG − 単勝支持率NDCG」を独立情報の代理指標**に（echo との二重チェック。※単勝支持率NDCGが高い＝市場エコー）。
4. **cyclical encoding**（季節 sin/cos）を低コストで導入。
5. **定性評価**（代表レース目視・海外馬などエッジケース）を軽く整備（過信は過学習なので参考程度）。
6. 上記適用後、**`walk_forward.py --quality` と回収率 OOS** で「123%」が honest に再現するか検証。再現しなければ市場効率の結論はより高確度で確定。
