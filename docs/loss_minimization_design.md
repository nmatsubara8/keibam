# 損失最小化フレームワーク（市場効率下の運用設計）

## 背景

35 年データ + 元ネタ動画チャンネルの全解析（約685ノート）により、**JRA 単勝市場は
効率的**（echo≈0.989, ΔR²≈0）で、公開データによる予測では市場を出し抜けないことが
確定した。動画の「回収率300%」は、①市場をなぞるモデル（単勝/人気が特徴量重要度
最大77%）、②買い目閾値の test 集合上での後付け最大化（`gain()`＋`n_bets>2`）、
③極小サンプル（315%=総投資額¥265=約3点）の合成 artifact であり、作者本人の正直な
全サンプル回収率は 82%（負け）だった。

予測で勝てない以上、任意のベットの期待損益は

```
E[P&L] = (EV − 1) × 投資額 ≈ −(控除率) × 回転量
```

に収束する。**唯一の合理的な最適化は「利益の最大化」ではなく「損失の最小化」**である。

## 3 つのレバー

予測精度は動かせないが、損失の出方は次の 3 点で操作できる。

### レバー1: 券種選択（控除率の最小化）
JRA 標準控除率は券種で異なる。**単勝/複勝 20%** が最小、三連単 27.5% が最大。
同じ回転量なら単勝の期待損失は三連単の約 0.73 倍。→ `src/constants/_takeout.py`

| 券種 | 控除率 | 払戻率 |
|---|---|---|
| 単勝・複勝 | 20.0% | 80.0% |
| 枠連・馬連・ワイド | 22.5% | 77.5% |
| 馬単・三連複 | 25.0% | 75.0% |
| 三連単 | 27.5% | 72.5% |

### レバー2: 回転量予算（turnover の制御）
賭けなければ損失 0。許容期待損失（娯楽予算）を先に決め、`上限回転量 = 予算 / 控除率`
で回転量の上限を導く。予算を守る限り期待損失は予算どおり。低控除ほど多く回せる。
→ `turnover_cap_for_loss_budget()`

### レバー3: 「賭けない」を既定とするゲート
`LossMinimizationConfig` は既定で最も保守的（単勝/複勝のみ・控除≤20%・EV>必要値）。
最重要は **`require_oos_threshold=True`**: 閾値/パラメータが OOS 検証済みでなければ
**一切賭けない**。これは「テスト集合上で回収率を最大化した閾値（=300%の主因である
後付け最適化）」を運用禁止にする構造的ガード。→ `src/policies/_loss_minimization.py`

資金配分（レバー3の下流）はエッジ≈0 ゆえケリー→0。賭ける場合もフラクショナル+上限で
ドローダウンを抑える（既存 `portfolio/_kelly` に委譲）。

## 実装

| ファイル | 役割 |
|---|---|
| `src/constants/_takeout.py` | 券種別控除率の単一定義元 + `rank_by_takeout` |
| `src/policies/_loss_minimization.py` | 3レバーの純粋関数/DTO（期待損失・回転量予算・ゲート・低控除優先） |
| `tests/policies/test_loss_minimization.py` | 21 ケース（全パス） |
| `verify_loss_minimization.py` | データ不要の数値デモ（`python verify_loss_minimization.py`） |

既存資産との接続:
- `policies/_takeout_calibration.py`: 払戻実績から実効控除率を逆算（Harville バイアス込み）。
  本表の標準値の代わりに実測 t_eff を使うと更に正確。
- `operation/_risk_guard.py`: 当日実現損失の kill switch（レバー2 の実運用側の停止装置）。
- `portfolio/_kelly.py`: `kelly_fraction` は EV≤1 で 0 を返す（エッジ無し→賭けない）。

## 立場

本フレームワークは**エッジを一切主張しない**。予測で市場を破る道は公開データでは
閉じている（Benter は独自加工特徴×低効率プール、Ranogajec はリベート由来で、いずれも
入手不能）。ここでの「最適化」は、参加するなら損失を娯楽コストとして最小・上限管理に
留めるための運用設計である。既定の数学的最適解は turnover=0（賭けない）。
