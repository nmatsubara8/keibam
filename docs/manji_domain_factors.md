# 卍式・加減点ドメインナレッジ・カタログ（Web収集）

卍氏(馬券裁判男)型の「回収率ベース加減点ファクター」を作るために、Web(netkeiba/umabi/
データ競馬系ブログ/note/学術)から収集した競馬ドメイン知識。6クラスタを並列リサーチして統合。

**凡例（実装タグ）**
- **即可**: JRAの公開列（着順/単勝/人気/枠番/馬番/性齢/斤量/馬体重/騎手/調教師/開催場/距離/芝ダ/馬場/日付/頭数/種牡馬名）＋既存の過去走特徴（interval, dist_change, kinryo_per_weight 等）だけで実装できる
- **要集計**: 外部データは不要だが、過去走履歴の自己集計ロジックが要る（乗り替わり判定・リーディング・キャリア数・叩き○走目・クラス復元 等）
- **要外部**: JRDB(IDM/基準オッズ/不利・出遅れ記憶要素)・レース映像・血統DB(母父/AEI)・外厩情報・気温 など、公開データに無い

> **最重要の注記**: 卍氏の妙味の核である「**前走で不利/出遅れ→着順が実力より悪く出た馬**」は、
> **公開データに存在せず JRDB の記憶要素やレース映像が必須（要外部）**。我々の前進検証で
> 0.858 止まりだったこととも整合する ── 行動因子の"見える半分"は作れるが、"効く核"は専有データ側。

最も工数が小さく、まず投入すべき群。**人気/オッズ帯**(1章1-8)、**前走着順系**(前走6着·前走11着カット·前々走連続·勝ち馬0.5/0.2秒差)、**枠順**(芝内/ダ外·芝スタートのダート·場別)、**距離短縮延長**(dist_change)、**ローテ間隔帯**(interval精緻化·若馬×長期明け·古馬減点)、**馬体重**(絶対値·前走比括弧値·kinryo_per_weight·極端増減)、**季節×性別×体重**(夏牝·冬牡·冬大型·夏3歳)、**種牡馬×芝ダ/距離/コース/馬場**(sire列があれば大量に作れる)。

### Tier 2 — 要自己集計（外部データ不要だがロジックが要る）
乗り替わり判定(前走騎手比較)、リーディング/騎手別ROI(期間集計)、騎手×調教師タッグ、キャリア数·叩き○走目·セン去勢初戦(過去走カウント)、クラス復元(賞金条件→昇降級)、路面替わり(過去race_type)。

### Tier 3 — 要外部データ（JRDB/映像/血統DB/外厩/気温）
**卍の核**である「**前走不利·出遅れ**」(JRDB記憶要素/映像)、**脚質·ペース·コーナー通過順·マクリ·当日トラックバイアス**(ラップ/通過順)、**基準オッズ·IDM·補正タイム**(JRDB)、**母父·ニックス·AEI·早晩**(血統DB)、**外厩情報**、**気温**(月で近似可)。

> **結論**: Tier 1+2 で卍の"見える半分"は相当量を再現でき、前進検証で 0.858 をどこまで押せるか
> 測れる。だが黒字化に効く核（前走不利/出遅れ·基準オッズ·脚質展開）は Tier 3=専有/映像側にあり、
> これが我々の 0.858→1.0 のギャップの正体、という当初の定量結論を裏づける。
