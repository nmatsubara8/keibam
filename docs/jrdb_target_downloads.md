# JRDB TARGET ダウンロードデータ 解析台帳

新モダリティ検証（STEP5）の入口。JRDB の TARGET 向けダウンロード（外厩/展開/番手/IDM 馬印・
成績IDM・各ランク）が、市場と直交する私的情報として予測に効くかを、**実ファイルを1つずつ解析**して
見極めるための台帳。方針: ページ HTML を読むより、実際に落ちたファイルを解析する方が早い。

既存の JRDB 標準データ（KYI/SED/SKB…）とは別系統。取込基盤（`src/jrdb/`）は流用可能だが、
本データのレイアウトは未知のため、まずキー・列・形式を確定してから配線する。

- 認証: env `JRDB_USER`/`JRDB_PASS`。スクレイピング間隔 ≥4 秒。セッショントークンはコミット禁止。
- 解析ヘルパ: `python scripts/jrdb_target_probe.py <file.zip|.lzh|.txt|dir>` で Phase2-3 を自動出力。

## 解析フェーズの定義

- **Phase2 実ファイル解析**: filename / size / encoding / record数 / 改行コード。（`jrdb_target_probe.py` が出力）
- **Phase3 フォーマット解析**: 固定長 / CSV / TSV / SJIS/UTF-8。TARGET 向けは固定長 or `RaceID,HorseNo,印` の可能性。
- **Phase4 キー解析（最重要）**: `RaceID` / `開催+日+R+馬番` / `血統登録番号` のどれか。→ DB 結合方法が決まる。
  - 参考: 標準 JRDB の race_id 規則・血統登録番号(ketto) は `src/jrdb/_augment.py` / `_keys.py` を流用可能か検証。
- **Phase5 情報量解析**: 印（◎○▲△）だけか、`外厩名/帰厩日/放牧先` 等の構造化情報か。
  - JRDB 公式では競走馬データ(KY)側に「放牧先/入厩年月日/入厩何日前/入厩何走目」が入るとの説明あり
    （外厩の"素の情報"が別データにある可能性）。

## 最短の進め方（推奨）

次の 3 ファイルを 1 つずつ取得し `jrdb_target_probe.py` にかければ、URL規則・圧縮・文字コード・
レコード構造・キー・TARGET 取込形式との対応がほぼ解明できる:

1. 外厩馬印（日次）1 ファイル
2. 外厩コメント（日次）1 ファイル
3. 成績IDM（年次）1 ファイル ← 指数の可能性が高く最優先

出力を本台帳へ転記 → 残りは同手順で機械的に埋める。キー確定後、`CI下限>1.0` ハーネス
（`myspeed_adoption_check.py` 系）へ載せて「市場と直交する純増分があるか」を検証する。

---

## 検証規律（維持）

- 目的は確率品質（＋私的情報の直交性）。ROI 判定は必ず OOS＋placebo＋レース単位ブロック bootstrap CI 下限>1.0。
- スクレイピングはポライトネス ≥4 秒。JRDB セッショントークン/認証情報はコミット禁止。
- 「印」系は市場が既に織り込んでいる公算。**成績IDM 等の指数**が市場未織込の私的情報かを重点検証。
