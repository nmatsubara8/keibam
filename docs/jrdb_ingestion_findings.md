# JRDB 取り込み — サンプル＋仕様解析でわかったこと

サンプルデータ(KYI/TYB/HJC/CSA/KSA/KTA/SED/SKB)＋各仕様書＋コード表を突合し、
byte-accurate なパースが可能になった。以下は確定事項。

## 1. 形式（全ファイル共通）
- 固定長テキスト、**Shift-JIS(cp932)**、レコード末 CRLF。
- レコード長: KYI=1024 / SED=376 / SKB=304 / TYB=128 / HJC=444 / KTA=388 / CSA=KSA=272（各仕様書の「レコード長」＝データ＋CRLF）。
- **注意: レースキーの「日」は数字F=16進1桁**（10〜15日は a〜f）。パーサで hex 解釈が必須。

## 2. 連携キー（確認済み・実データで検証）
- **レースキー(8)** = 場コード(2)+年(2)+回(1)+日(1,hex)+R(2)。レース単位（番組/HJC払戻/基準オッズ）。
- **+馬番(2)** = 出走馬単位（KYI前日/TYB直前/SED・SKB成績）。
- **血統登録番号(8)** = 同一馬を時系列で連結 → **今走KYIの馬を、過去のSED/SKB（年月日<今走）に血統登録番号で紐付け = 前走特記/不利/出遅れ**（リーク無し）。
- 馬名は cp932 で正しくデコード（例: KYI「ウェルノーテッド」）。

## 4. Tier-3「要外部」ギャップが、すべて実ソースで埋まる

ドメインナレッジ・カタログで「要外部(JRDB/映像)」としていた因子の出所が確定:

| カタログの"要外部"因子 | JRDBソース@相対 |
|---|---|
| **前走 不利/出遅れ/位置取り**（卍の核） | SKB特記@27（387不利…）＋ SED 出遅@195/不利@201/位置取@198 |
| 脚質・展開 | KYI脚質@90 / SED レース脚質@341 |
| 距離適性 | KYI距離適性@91 |
| 能力指数(IDM) | KYI IDM@55 / SED IDM@183 |
| **基準オッズ**（Benter核） | KYI基準オッズ@96 |
| 蹄・脚元 | SKB脚元@69 |
| 馬具(ブリンカー装着/変更) | SKB馬具@45 |
| 前走ペース(H/M/S) | SED レースペース@222 |
| 乗り替わり | KYI参考前走騎手@530 / 騎手コード@336 |

→ **0.858→1.0 のギャップを埋める材料が、位置まで含めて全部そろった。**

## 5. 唯一の実装課題＝JRDB↔netkeiba キー橋渡し
既存 featured は netkeiba 由来（race_id, horse_id）。JRDB は レースキー(場+年+回+日+R) と
血統登録番号。**両者の決定的マッピングが取り込みの要**:
- レースキー(場2+年2(西暦下2)+回1+日1hex+R2) ↔ netkeiba race_id(西暦4+場2+回2+日2+R2)。
  場コードは同一採番、年は世紀補完、日は hex→10進 で変換可能（決定的）。
- **血統登録番号(8) ↔ netkeiba horse_id** ← ここが要検証（桁・採番が異なる。突合表 or 馬名+生年での照合が要るかも）。

## 6. 系統コードの所在（要注意・訂正）
今回サンプル(KYI/KTA)には **系統コード/父馬名フィールドが無い**（連携図の読みは誤り）。
per-horse の系統/父馬名は **馬基本データ（今回未添付）** にあると見られる。
→ 先行実装した「種牡馬名→系統シード」は、馬基本データ到着まで**橋渡しとして有効**。

## 7. リーク防止（必須）
SED/SKB は結果データ（レース後確定）。因子化では **年月日<今走 の過去走のみ** を
血統登録番号で結合する。walk-forward/前進検証は既にこの時系列分離を担保できる。

## 8. 次段の実装計画
1. **キー橋渡し**（レースキー↔race_id、血統登録番号↔horse_id）を確立。← 最初の関門。
2. **固定長パーサ**（cp932・hex日・上記オフセット）で KYI/SED/SKB を読む。
3. **前走特記の紐付け**（今走馬 × 過去SED/SKB, 年月日<今走）→ 「前走不利」「前走出遅れ」等を factored。
4. **基準オッズ・IDM・脚質・距離適性** を KYI から featured に付与。
5. manji 因子に追加 → 前進検証＋プラシーボで 0.858 が動くか実測。
