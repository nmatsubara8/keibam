# JRDB TARGET 追加データ 仕様台帳

会員ページで配布されている TARGET 用追加データ（外厩コメント／各種馬印／成績IDM／厩舎・騎手ランク）の
**取得手順・ファイル形式・結合キー・発表時点・既存取込との重複**を確定するための台帳。

進行方針は **B → C → A**（現物確認 → 台帳確定 → 研究着手）。理由: 「外厩コメント＝新規テキスト」
「成績IDM/騎手/厩舎ランク＝既存取込済み」は **現物照合前は未確定**であり、推論で確定扱いにしない。

> ステータス凡例: ✅確定（コード or 現物で照合済） / 🟡暫定（1サンプルからの推定・要全年度確認） / ⬜未取得

最終更新: 2026-07-31（全8種の取込パイプラインを本ブランチへ統合＝§8。外厩コメントの正規化/年補完/
センチネル処理を移植。残: 成績IDM=SED値照合、G1 純増分検証、ランク=日次スナップショット蓄積）

## 0. 確定済みの事実

### 0.1 左辺キー = 既存 race_key + umaban（✅ `src/jrdb/_keys.py` で照合済）

外厩コメントの左辺 10 桁キー（例 `0126120103`）は **新しい変換規則を要さない**。

```
0126120103 = race_key(8) + umaban(2)
  01  26  1   2      01   03
  場  年  回  日(hex) R    馬番     → 札幌 2026 1回2日目 1R 3番
```

```python
from src.jrdb._keys import race_key_to_race_id
race_id = race_key_to_race_id(key[:8])   # 日は16進1桁・世紀補完(pivot=86)込み
umaban  = int(key[8:10])
# (race_id, umaban) で featured / KYI / SED と結合 ← 既存 JRDB join と同一キー
```

- **日は 16 進 1 桁**（10〜15 日目 = a〜f）。左辺を 10 進で桁分割しないこと。
- ファイル名 `YC012612.DAT` = `YC` + 開催キー6桁（`01`場 `26`年 `1`回 `2`日）。**1 ファイル = 1 開催**。

## 3. 外厩コメントの構造（✅ 日次+年次を現物解析＝確定。日次284/284・年次16724/16724 で 100% パース）

- **自由記述テキストではなく定型構造化文字列**を確定 → NLP 不要・辞書/embedding 不要。
- 配布/ファイル形式（現物確認済）:
  - 日次 ZIP 名 = `gaikyucomment_<YYYYMMDD>.zip`、年次 ZIP 名 = `gaikyucomment_<YYYY>.zip`。
  - ZIP 内 = 開催ごとに `YC<開催6桁>.DAT`（例 `YC012612.DAT` = 場01年26回1日2）。1 開催 = 1 ファイル。
    年次は 1 年分の全開催（2026 で 167 ファイル）。**`YC02261a/1b/1c.DAT` の a/b/c で日=16進を実証**。
  - **CP932 / CRLF / ヘッダなし CSV / 1 行 1 頭 / カンマ 1 個**。日次・年次で同一形式。
  - 左辺 = 10 桁キー、右辺 = `外厩名　MM/DD　中N週`（区切りは全角スペース `　`）。
- 抽出列: `target_key` / `raw_comment`（無加工保持）/ `gaikyu_name` / `gaikyu_date_raw`(MM/DD) / `interval_weeks`。
- 派生: `has_gaikyu`（この左結合に**存在するか**＝外厩利用の有無。ファイルは外厩利用馬のみ収録）/
  `days_since_return`（帰厩日→出走日。ただし出走日は race_id から別途取得）。

### 3.1 確定パーサ正規表現（日次 284/284・年次 16724/16724 = 100.000%）

日付と週数の**両方を任意**にするのが最終形（日次では週数空欄のみ、年次でさらに日付欠損が出た）:

```python
COMMENT_RE = re.compile(
    r"^(?P<gaikyu_name>.+?)　(?P<date>\d{2}/\d{2}|/)　中(?P<weeks>\d*)週$"
)
# date == "/"      → gaikyu_date_raw = None（帰厩日欠損）
# weeks == ""      → interval_weeks  = None（前走間隔なし＝初出走等。年次で 12.9%）
# name == "情報無し" → gaikyu_name    = None（外厩利用はあるが牧場名不明。年次 4 件）
# name が全角数値(例 ９９．９) → gaikyu_name = None（欠損センチネル。年次 3 件）
```

観測された例外（年次 16,724 件で網羅）:
| 例外 | 例 | 件数 | 扱い |
|---|---|--:|---|
| 週数空欄 | `…　中週` | 2164 | `interval_weeks=None`（初出走等） |
| 日付欠損 | `外厩名　/　中N週` | 6 | `gaikyu_date_raw=None` |
| 外厩名不明 | `情報無し　/　中N週` | 4 | `gaikyu_name=None`, `has_gaikyu=True` |
| センチネル名 | `９９．９　…` | 3 | `gaikyu_name=None` |
| 年越し帰厩日 | 帰厩 12/xx で年初出走 | Dec1740/Nov165 | 出走日基準で年推定（帰厩月>出走月なら前年） |

- `連闘`・`初戦`・`放牧`・地方/海外表記は年次でも **0 件**（この配布では発生しない）。
- 外厩名ユニークは 1 日 59 → 1 年 **173**。**稀少名の高次元 one-hot は禁止**、履歴化/グルーピングで扱う（§6.1）。

### 3.2 `中N週` の意味 = 前走からの競走間隔（✅ 実証・滞在週数ではない）

帰厩日と桁が桁違いに乖離する実例で確定:

```
ダーレー・ジャパン  帰厩07/10(出走2026-07-26の16日前)  だが 中44週(=308日)
ビッグレッドＦ鉾田  帰厩06/19(出走の37日前)          だが 中55週(=385日)
```

- **MM/DD = 外厩から厩舎へ戻った帰厩日**（直近 16〜45 日）、**中N週 = 前走からの競走間隔**（最大 55 週）。両者は別概念。
- `中N週` を「外厩滞在週数」とみなしてはならない（特徴設計の禁止事項 §6.1 に反映済）。
- 週数空欄（`中週`）30 件は前走なし（初出走等）の可能性 → `interval_weeks = None`。SED 前走日との突き合わせで最終確認する。

### 3.3 残る未確定

- **他年度（2016 等）**でも同一形式か（2026 のみ確認済。命名・キー・例外語は安定と予想だが未検証）。
- `中N週` = SED 前走間隔と厳密一致するかの数値照合（このコンテナに SED 実データが無いため保留）。
- `情報無し`/センチネル `９９．９` が全年度共通の欠損表現か（2026 で確認、要通年）。

## 6. A: 外厩運用情報の純増分検証（B/C 確定後に着手）

研究テーマは「外厩コメントのテキスト分析」ではなく **「外厩運用情報の構造化特徴量としての純増分検証」**。

### 6.1 特徴量（すべて過去走のみ・fold 以前）

- 低コスト: `has_gaikyu` / `gaikyu_name` / `days_since_return` / `interval_weeks` /
  `gaikyu_name × interval_weeks` / `gaikyu_name × trainer`
- 履歴集約: 外厩別複勝率 / 外厩別 market-residual / 外厩×厩舎別成績 / 休み明け成績 /
  同一外厩継続利用時の成績 / 外厩変更時の成績
- **避ける**: 全期間 target encoding / 評価期間を含む集約 / 出走後更新ファイルの利用 /
  稀少外厩の高次元 one-hot / `中N週` を外厩滞在週数とみなすこと

### 6.2 段階ゲート（MySpeed 流・過去走のみ厳守）

1. **Phase 0 情報独立性**: 新feature vs 市場(IDM/基準オッズ/人気/確定オッズ)の相関・偏相関。冗長なら即棄却。
2. **Phase 1 較正ゲート**: OOS で ΔNLL/ECE を `_model_compare`、placebo 2軸(残差/オッズ)対照。
3. **Phase 2 ROIゲート（唯一の合否）**: `multibet_roi_test` のレース単位ブロック bootstrap **95%CI下限>1.0**。
   帯・サブセット選択は train のみ、多重比較は placebo で検定。
4. **Phase 3 運用配線**: 通れば EV較正＋損失最小化へ。通らなければ「効率市場の再確認」として記録。

## 8. 実装（本ブランチに統合済・全8種）

取込パイプラインは `review-context-and-tasks-1vxigl` の step5 実装を本ブランチへ取り込み、
外厩コメントの正規化・年補完・センチネル処理を移植して統合した。

- **`src/jrdb/_target.py`**: 全8種のパーサ。zip 名先頭英字で `classify`、`read_jrdb_bytes` で
  zip/lzh 展開、種別ごとに正規化 DataFrame。自然キー `NATURAL_KEYS` で重複除去
  （ランクは `source_date×person_code` で時系列保持＝as-of 結合可）。
  - 外厩コメント: `gaikyu_name`(NFKC正規化)＋`gaikyu_name_raw`(生値)、`情報無し`/`９９．９`→NA、
    帰厩日欠損 `/`→空、`complete_return_date`/`kikyu_month_day`（年跨ぎ補完 primitive）。
- **`scripts/jrdb_target_ingest.py`**: `--src <dir> --out-dir <dir>`。sha1 内容重複排除・未分類/読取不可の
  可視化・種別ごと正規化 pickle 出力。日次⊂年次の重なりは自然キー dedup（例: 外厩コメント 生17008→16724）。
- **テスト**: `tests/jrdb/test_target.py`(33件 green)。中週空欄/日付欠損/センチネル/年跨ぎを回帰固定。

実行例:
```
python scripts/jrdb_target_ingest.py --src /mnt/c/Users/Ayaka/Downloads --out-dir data/jrdb_target
```

### 残作業
- 成績IDM `seiseki_idm` × `SED[idm]` の値照合（一致率/最大絶対差）。要 SED 実データ。
- G1: 外厩 raw4 特徴（has_gaikyu/gaikyu_name/days_since_return/interval_weeks）を production baseline に
  加えた OOS ΔLogLoss/ΔAUC/ECE 判定。要 featured＋production model（本コンテナ外）。
- ランクの予測利用は日次スナップショット蓄積が前提（現在版の過去一括適用はリーク）。
